# plario-automation

Скрипты для работы с диагностикой и адаптивным тренажёром на my.plario.ru через их внутреннее API. Всё писалось под свой аккаунт и свой курс, просто чтобы не кликать руками сотни однотипных заданий.

Никакой магии внутри нет. Я открыл девтулзы, посмотрел какие запросы шлёт фронт, и повторил их на питоне. Токен используется ровно тот же самый, который получает обычный залогиненный пользователь в браузере.

## Идея

Всё держится на трёх скриптах.

**collect.py** ходит по платформе и складывает в один json список модулей с их названиями, статусы диагностики и все задачи с условиями и вариантами ответов.

**send.py** берёт этот json, на каждую задачу спрашивает ответ у решателя и отправляет его.

**trainer.py** крутит адаптивный тренажёр, где задачи выдаются по одной и правильность видна сразу.

Отдельно лежит **solver.py**, это заглушка с выбором ответа. Сейчас там осознанно ничего не решается, туда надо воткнуть вызов ии. Оба скрипта, и send.py и trainer.py, ходят именно в него, так что подключать нейронку нужно ровно в одном месте.

## Что нужно на старте

Питон третий, `requests` из requirements.txt. Ставим зависимости

```bash
pip install -r requirements.txt
```

Дальше нужен свежий Bearer токен. Логинимся в my.plario.ru, открываем девтулзы, вкладка Network, тыкаем любой запрос на api.plario.ru и копируем весь заголовок Authorization целиком, вместе со словом Bearer в начале. Кладём это одной строкой в token.txt

```bash
cp token.txt.example token.txt
```

Токен живёт часов пять, потом протухает и его надо перевыпускать тем же способом. Скрипты это переживают нормально, send.py например словит 401, встанет на паузу и будет раз в пять минут проверять не обновили ли вы файл. token.txt лежит в .gitignore, так что случайно закоммитить его не получится.

Если у вас другой курс, свой id прокидывается переменной окружения

```bash
export TEACHER_COURSE_ID=1234
```

По умолчанию стоит 2734, это тот курс на котором всё крутилось у меня. Узнать свой можно запросом `GET /learner/course/available`, collect.py его и так дёргает и кладёт название курса в выгрузку.

## solver.py, сюда подключается ии

Весь выбор ответа живёт в функции `ask_ai(task)`. Сейчас она просто кидает `AnswerNotResolved` с описанием того, что от неё ждут. На вход прилетает словарь такого вида

```python
{
  'activityId': 2817,
  'skill': 'Определять формулу по графику',
  'condition': 'Найдите формулу для функции, заданной графически',
  'condition_html': '<p>Найдите формулу ...</p>',
  'images': ['https://plario.ru/content-resources/adf4d2c6.png'],
  'options': [
    {'answerId': 10491, 'text': '\\(y=2^x+1\\)', 'text_html': '...', 'images': []},
    {'answerId': 10490, 'text': '\\(y=e^x+2\\)', 'text_html': '...', 'images': []}
  ]
}
```

Вернуть надо `answerId` того варианта, который считается правильным. Формулы приходят в латехе прямо как на сайте, а если в задаче или в вариантах есть картинки, их ссылки лежат в `images`, так что мультимодальной модели можно скормить и их тоже.

Вокруг заглушки уже сделано всё остальное. Есть кэш в data/answers_cache.json, куда сложены 134 ответа по диагностике, которые я в своё время решил руками. `solve()` сначала смотрит туда и только потом дёргает ии, так что готовое второй раз решать не придётся. Если модель вернула answerId, которого вообще нет среди вариантов задачи, это ловится сразу и такая задача уходит в пропуск, а не улетает на сервер мусором. Подтверждённые тренажёром правильные ответы тоже дописываются в кэш автоматически.

Отключить кэш можно флагом `--no-cache` у обоих скриптов.

## collect.py

Собирает всё что есть по курсу в один файл data/diagnostic.json.

```bash
python3 collect.py
python3 collect.py --module 5
python3 collect.py --start-diagnostic
```

Внутри дёргаются четыре ручки. `GET /learner/course/available` отдаёт название курса. `GET /learner/mastery/statistics/info` отдаёт список модулей с названиями, текущим mastery и порогом. `GET /learner/diagnostic` отдаёт статус диагностики по модулю. `GET /learner/diagnostic/start` отдаёт сами задачи с условиями и вариантами.

Флаг `--start-diagnostic` нужен если по модулю диагностика ещё вообще не начата, тогда перед выгрузкой задач скрипт стукнет в `POST /learner/diagnosticAttempt/start`. Без него скрипт ничего не начинает и просто читает, так что гонять collect.py безопасно сколько угодно раз.

На выходе получается примерно такое

```json
{
  "collectedAt": "2026-09-18T22:30:00",
  "teacherCourseId": 2734,
  "course": {"id": 2734, "name": "Элементарная математика ИПМКН 2026"},
  "modules": [
    {
      "moduleId": 1,
      "moduleName": "Преобразование алгебраических выражений",
      "mastery": 70, "threshold": 0.9,
      "diagnosticStatus": "TestStarted",
      "tasks": [{"activityId": 107, "condition": "...", "options": [...]}]
    }
  ]
}
```

## send.py

Читает выгрузку, на каждую задачу спрашивает ответ у solver и отправляет.

```bash
python3 send.py --dry-run
python3 send.py --limit 3
python3 send.py --module 5
python3 send.py
```

Первым делом советую прогнать с `--dry-run`, он ничего не шлёт и просто показывает что и куда полетело бы. Потом `--limit 3` на пару задач, и только потом целиком.

Отправка одного ответа это два запроса. Сначала `POST /learner/diagnostic/activities/{activityId}/attempts`, он возвращает число, которое и есть answerSubmitId. Потом `POST /learner/attempt/answer/{answerSubmitId}/{answerId}`. Важно что answerSubmitId выдаётся заново на каждую попытку и протухает вместе с сессией, поэтому он не хранится в выгрузке, а берётся прямо перед отправкой.

Между задачами пауза от 133 до 237 секунд, рандомная. Смысл в том что 134 запроса подряд без пауз это очевидный бот и есть шанс словить бан от WAF, а с такой паузой трафик выглядит как человек который сидит и честно листает задачи. Меняется флагами `--min-delay` и `--max-delay`.

Прогресс пишется в data/send_progress.json после каждой задачи, так что скрипт можно прибивать Ctrl+C и запускать заново, уже отправленное он второй раз не тронет. Лог лежит в data/send_log.txt.

## trainer.py

Тренажёр выдаёт по одному заданию на модуль. Это либо теория с кнопкой продолжить, либо задача с вариантами. За каждый правильный ответ растёт mastery по навыку, порог освоения 90 процентов. Когда все навыки модуля взяли порог, модуль закрывается.

Пять команд на все случаи жизни.

```bash
python3 trainer.py next 3
python3 trainer.py submit 3 970 10148225 104
python3 trainer.py complete 3 571 10148038
python3 trainer.py stats 3
python3 trainer.py run 3
```

`next` показывает текущее задание и сразу открывает по нему попытку, печатает activityId, attemptId, навык, условие без html мусора и все варианты с их answerId.

`submit` отправляет ответ, аргументы это модуль, activityId, attemptId, answerId. В ответе прилетает rightAnswerIds, по нему видно попали вы или нет.

`complete` закрывает теорию, аргументы те же самые только без answerId.

`stats` показывает mastery по модулю и список навыков ниже порога, удобно смотреть до чего осталось дотянуть.

`run` это полный автомат. Крутит цикл сам, теорию закрывает молча, на задачах идёт в solver. Пока решатель не подключён, на первой же задаче он честно остановится, напечатает её целиком и выйдет. Есть предохранитель `--max-steps` со значением 200 по умолчанию, чтобы не уйти в бесконечный цикл, и `--delay` на паузу между заданиями.

Заканчивается модуль одним из двух. Либо `{"activityStatus":"Mastered","exercise":null}`, и это значит что все навыки взяли порог. Либо `{"activityStatus":"NoMoreActivity","exercise":null}`, и это значит что задания в банке кончились раньше чем навыки добрали проценты. У меня так было на седьмом модуле, пять навыков так и остались ниже порога, а давать по ним задачи тренажёр отказался.

## Грабли

**checkAnswer одноразовый.** Отправили ответ и всё, переотправить другой по этой же попытке нельзя. Так что сначала решаем, потом шлём, а не наоборот.

**completeLesson хочет activityId, а не knowledgeComponentId.** Вот на этом я знатно посидел. Эндпоинт упорно отдавал 404 с ModuleSessionNotFoundOrExpired, я успел решить что это баг платформы, и только разобрав main.js увидел что первым параметром пути идёт activityId текущего задания. А я туда пихал id навыка, который выглядит точно так же, обычное трёхзначное число. Плюс в query обязательно нужны moduleId и teacherCourseId, без них тоже ничего не работает. Правильный вызов такой

```
POST /learner/adaptiveLearning/completeLesson/{activityId}/{attemptId}?moduleId={m}&teacherCourseId={tc}&culture=ru
```

После фикса отработало больше четырёхсот раз подряд без единого сбоя.

**answerId не проверяется на принадлежность задаче.** Бэк спокойно принимает answerId от совершенно другого задания. Поэтому в solver.py стоит своя проверка, что вернувшийся id вообще есть среди вариантов этой задачи.

**answerSubmitId одноразовый.** Тот что лежал в старых выгрузках, после перезапуска сессии уже не работает. Поэтому send.py берёт его сам прямо перед отправкой.

## Что лежит в репозитории

plario.py это клиент к api, там собраны все ручки и обработка токена. solver.py это заглушка с выбором ответа. collect.py, send.py и trainer.py это три рабочих скрипта. В data лежит кэш готовых ответов, туда же пишутся выгрузка, прогресс и логи, но они уже в gitignore.

## Дисклеймер

Работает только с вашим собственным токеном и вашим собственным аккаунтом. Чужой токен сюда совать нельзя, это уже совсем другая история и к задаче для которой это писалось она отношения не имеет.
